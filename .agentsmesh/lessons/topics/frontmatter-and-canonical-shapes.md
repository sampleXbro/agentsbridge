# Lessons: frontmatter & canonical entity shapes

## Rules (apply unconditionally)

1. Every third-party YAML frontmatter parse on install/import paths — whether the file is `SKILL.md`, command, agent, rule, MDC, or skill-name extraction (`readSkillFrontmatterName()`) — MUST use `tryParseFrontmatter()` / `parseFrontmatterForPath(..., onError)` and emit a "skipping <path>: <reason>" warning on failure. Reserve strict `parseFrontmatter()` exclusively for user-authored canonical content under `.agentsmesh/`.
2. When auditing parser changes, grep both `parseFrontmatter` AND every per-target importer (`src/targets/<id>/importer*.ts`) plus every auxiliary helper (skill-name extraction, MDC inference, name detection) before declaring the lenient-parsing fix applied.
3. NEVER add files under `.agentsmesh/skills/<name>/` beyond `SKILL.md` and ordinary supporting files (`references/`, `scripts/`, `templates/`, `assets/`). Do not invent `agents/openai.yaml` or other shapes — the canonical skill spec is `SKILL.md` + supporting files only.
4. NEVER write a literal `*/` inside any `/* ... */` or JSDoc block comment — including header comments in test files. Replace glob-shaped paths in prose (e.g. `.agentsmesh/skills/*/SKILL.md`) with `skills/{name}/SKILL.md` or `glob: *.md`, or move the glob into a single-line `//` comment outside the block.
5. Canonical booleans derivable from the destination path or artifact kind (notably `root: false` on non-root rules) MUST be derived and serialized in one shared helper, never left to per-target importer habits. Add cross-target tests that assert the exact canonical frontmatter contract.
6. Manual install staging and persistence MUST share one skill-name derivation helper. If staging reads the name via `readSkillFrontmatterName()` from `SKILL.md` frontmatter, persistence (`pick.skills`) MUST use the same source — never `basename(contentRoot)` on one side and frontmatter on the other.
7. Any synthetic canonical entity created from a non-frontmattered source (e.g. `.cursorrules` / `.windsurfrules` root files, marketplace stubs) MUST carry a non-empty `description` (e.g. `Imported from .cursorrules`). Empty descriptions pass unit tests but get dropped by `resolveRulePool()`'s `validateRule` re-filter under `dryRun=true`, even with `--force`.
8. Projected-agent test fixtures MUST be built from the documented `serializeProjectedAgentSkill()` output: real `x-agentsmesh-kind: agent` plus `x-agentsmesh-name` (or an `am-agent-*` directory). NEVER invent flags like `x-projected-agent: true`. Assertions must lock the exact canonical `.agentsmesh/agents/<name>.md` destination.
9. Filter "boilerplate" files by intent, not by a single blanket predicate. Maintain one typed map (`stem → 'noise' | 'preserved'`) with three derived predicates: `isBoilerplate` (prevent phantom entities in entity importers / flat-collection classifiers), `isNoiseBoilerplate` (drop in staging + skill supporting-files), `isPreservedBoilerplate` (keep LICENSE/NOTICE/COPYING/README in skill subtrees AND at pack root for legal attribution + consumer context). Both `listSupportingFiles` and `cpFilteredSkill` must use the noise-only predicate at content-staging time.
