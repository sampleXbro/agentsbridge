# Lessons: generation, collision, output-source maps

## Rules (apply unconditionally)

1. Whenever a target generates more than one file from the same canonical source, audit the output-source map against the full generator output list so every emitted path participates in rewriting and collision logic — never assume "one canonical → one artifact". See L128.
2. When a layout declares `additionalRootDecorationPaths`, add those decoration paths to generate-side source maps and test at least one nested Markdown mirror for canonical link cleanup; decoration paths are generated artifacts, not render-only metadata. See L63.
3. When a target can emit multiple artifact families from the same canonical source (e.g. Copilot `.github/copilot/*.instructions.md` and `.github/instructions/*.md`), build and cache rewrite maps per output path or per artifact family — never key only by target. Add tests for each emitted path family. See L131.
4. When resolving conflicting shared artifacts by choosing a preferred/richer content body, keep that chosen result's `status`/`currentContent`; only merge statuses for truly identical content. Never let a discarded result donate drift status to the kept artifact. See L41.
5. When multiple targets share one output path, compare outputs after normalizing target-specific references back to canonical paths before deciding they conflict; add coverage for rewritten-content overlaps. See L123.
6. When skills can originate from packs, add pack-path→target-path entries to the artifact map (alongside canonical `.agentsmesh/skills/...` entries) so the reference rewriter can translate both canonical and pack absolute paths. See L162.
7. When appending global instructions / root-instruction decoration to generated targets, phrase the canonical location without the literal `.agentsmesh/` substring (e.g. "the `.agentsmesh` directory at the project root"), keep legacy paragraph detection for upgrades, and strip both old and new contract blocks on import in the shared root-rule import path. Cover with round-trip e2e. See L92, L163.
8. When adding a secondary rule projection folder for a target that already has a primary root file (e.g. Codex `AGENTS.md`), default to mirroring only non-root / additional rules — never duplicate the primary root file unless the spec explicitly requires it. See L164.
9. When enabling a new artifact family for a target, update `reference-map-targets` + import-reference map builders + importer scanners together; do not ship generator/importer surface files first and patch path-translation contracts later. Verify with the target-contract matrix e2e. See L151.
10. When an importer maps reserved/generated source artifacts back into canonical files, add strict re-import tests that preseed stale outputs (`_ab-agent-*`, `_ab-command-*`, hidden scoped rules) and verify the importer removes them — import is not write-only. See L145.
11. When two targets implement the same import filter/cleanup pattern (e.g. Codex and Windsurf), move the logic into a shared helper and verify both targets against the same strict regression cases — never copy-paste per-target cleanup. See L146.
12. When importing any target artifact, build the normalization map from every supported generated path family so re-import can recover canonical `.agentsmesh/...` links from previously polluted outputs (e.g. cline / claude-code reading Codex-style `.agents/...` links). Never assume same-family pristine inputs. See L147.
13. When one canonical feature emits multiple artifact families (e.g. Copilot hook JSON + wrapper scripts), centralize the eligibility predicate ("is this hook runnable?") in one shared helper and add a regression test comparing referenced artifacts against emitted files. Never duplicate "is valid" logic per generator. See L140, L149.
14. When a target generator intentionally drops canonical metadata (e.g. Codex CLI MCP `description`), add or update a target-specific lint warning and cover with unit + CLI e2e tests; unsupported metadata is part of the target contract users must see. See L143.
15. When tests verify generated files or directories, assert the exact relative path set and exact count, and cross-check referenced artifacts (e.g. hook wrapper scripts) against the config that points to them — no `some(...)`, prefix-only, or "at least one" checks. See L139.
16. When a target-format cannot represent all canonical metadata (e.g. Cursor command `description`/`allowed-tools`), add strict re-import-into-existing-project tests that prove unsupported fields are preserved from the canonical destination rather than erased. Empty-project round trips are insufficient. See L144.
17. When widening a core type into a union (e.g. `McpServer` gaining URL transports), add explicit type guards at every serializer/generator boundary that needs a specific variant and rerun `pnpm typecheck` before declaring the refactor done. See L121.
18. In `resolveGen` (engine), check `getBuiltinTargetDefinition(target)` first; if present, delegate entirely to `resolveTargetFeatureGenerator(target, feature, config)` so conversion config (e.g. `commandsToSkills: false`) is always respected. Plugin registry fallback must not bypass builtin conversion logic via `getDescriptor`. See L184.
19. When a command validates multiple canonical features in `runLint()`, gate each lint family (commands, MCP, permissions, hooks) by its own feature flag — never nest them all under `hasRules`. Add a regression test for configs that enable non-rule features without `rules`. See L155.
20. When multiple targets share a common parent directory in global mode (e.g. `.gemini/`), each non-native target must use a namespaced subdirectory (Antigravity → `.gemini/antigravity/`) to avoid path collisions; the collision detector only special-cases `AGENTS.md`. See L176.
