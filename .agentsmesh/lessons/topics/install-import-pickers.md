# Lessons: install, import, pickers

## Rules (apply unconditionally)

1. Treat `as` on `InstallTarget` as a routing decision, not a feature label. Only set `as` for **flat-collection** sub-packs (no `skillPack`/`rootSkill` marker); leave `as` undefined for skill-pack / root-skill sub-packs so recursion re-runs auto-discovery at the sub-pack root. Always plumb `report.subPackFailures` into `InstallData` so the CLI renderer surfaces partial failures. [L3, L37]
2. Every third-party frontmatter parser on the install/import path — including auxiliary helpers like skill-name extraction (`readSkillFrontmatterName`) and `.mdc` inference (`inferMdcTarget`, `normalizeMdcToCanonical`) — must use `tryParseFrontmatter()` / `parseFrontmatterForPath(..., onError)` and degrade with a "skipping <path>: <reason>" warning. Reserve strict `parseFrontmatter()` for user-authored canonical content. Audit by grepping both `parseFrontmatter` and every `src/targets/<id>/importer*.ts`. [L31, L35, L268]
3. Normalize empty-string CLI flags (`path`, `target`, `as`) to `undefined` inside `readInstallFlags`. Picker auto-pick recursion in `run-install-locked.ts` builds nested flag bags with `target ?? ''`; the rest of the pipeline assumes "undefined OR non-empty". [L33]
4. Marketplace `--all` recursive installs must omit `--as` (only pass `--path` and `--target`) — `targetFromSubPack`'s first-feature inference forces the manual single-kind path which rejects mixed-content sub-packs. [L37]
5. Lower the picker's marketplace-branch threshold to `subPacks.length >= 1` when sub-packs come from explicit sources like `.claude-plugin/marketplace.json`. Singleton plugin lists must route through the marketplace branch, not `runSinglePackInstall` against an empty root. The directory-heuristic detector keeps its own `>= 2` floor. [L272]
6. Nested `runInstall` calls from picker auto-pick (single flat collection branch) MUST pass `replay ?? {}` as the 4th arg so the inner `if (replay === undefined)` guard skips `acquireInstallLock()` re-acquisition. Otherwise the inner call deadlocks against the outer's held lock. [L270]
7. `install --sync` replay must reapply persisted `features` + `pick` from `installs.yaml` before validation/selection (not just the saved path), must carry through the caller's `--force` and related validation flags (never hardcode `force: true`), and the replay parser must accept persisted internal source formats (`github:org/repo@sha`, `blob/...` URLs), not only user-entered URLs. [L99, L100, L101, L98]
8. `install --sync --dry-run` is not provably side-effect free — validate in isolated temp projects or inspect the implementation before pointing it at a live workspace. [L160]
9. Persist manual single-item installs by **parent collection path + explicit `pick`**, never the discovered file path. Pack names must describe stable source identity + normalized install scope (not first-picked-item naming). For broader-than-one-path identity, persist aggregated `paths` and match packs by repo identity + feature set so sync replay across multiple folders of the same repo/feature works. [L97, L153, L154]
10. Manual install persistence and staging must share one skill-name derivation. If staging uses `readSkillFrontmatterName()`, persistence must use the same helper — never `basename(contentRoot)`. [L161]
11. When manual skill replay carries `pick.skills: [name]` but `path` is a collection root (e.g. `skills` or `skills/engineering`), search **all descendant `SKILL.md` paths** under the source root and stage the exact matched skill directories. Don't restrict to umbrella folders that themselves have `SKILL.md`. [L156, L159]
12. Replay/scoped install narrowing must reach `installAsPack()` — pass the narrowed canonical through every downstream write/materialization path so unrelated settings (`mcp`, `permissions`, `hooks`, `ignore`) don't leak into the resulting pack. [L158]
13. Provide an explicit `--as` override that bypasses native-path heuristics; keep native auto-detection as fallback. Install discovery must not be coupled to target-native directory layouts for arbitrary folders. [L102]
14. Native install discovery is **read-only staging**. Import into a temporary staged copy and derive folder/file scope from importer `fromPath` results — never mutate the source checkout or heuristically traverse it for subtree selection. [L104]
15. Incremental pack updates must match by **stable remote identity** (provider + repo/url without ref), not the pinned `github:org/repo@sha`. Refresh stored `source`/`version` metadata after each successful merge. Preserve existing on-disk cache paths when refactoring cache-backed providers. [L105, L119]
16. Single-file remote install parsing must cover both `tree/...` (directory) and `blob/...` (file) URLs per supported host. [L98]
17. Pack coverage must include settings features (`mcp`, `permissions`, `hooks`, `ignore`) — not just array resources. Write → load → generate tests must include a real non-dry-run command path. [L103]
18. Synthetic root-rule canonical entries (`.cursorrules`, `.windsurfrules`, marketplace stubs) MUST carry a non-empty `description` (e.g. `Imported from .cursorrules`) so they survive the dry-run-only re-validation pass in `pool-resolution.ts` (`resolveRulePool` filters by `validateRule` when `dryRun=true`). [L274]
19. Boilerplate filtering splits intent via one typed map (`stem → 'noise' | 'preserved'`) and three derived predicates: `isBoilerplate` (any — used by entity importers + flat-collection classifier to prevent README/LICENSE from becoming phantom entities), `isNoiseBoilerplate` (drop in staging + skill supporting-files), `isPreservedBoilerplate` (keep in skill subtrees). Both `listSupportingFiles` (canonical/features/skills.ts) AND `cpFilteredSkill` (install/source/skill-repo-filter.ts) must use the noise-only predicate at content-staging time. [L276]
20. Plumb upstream `contentRoot` end-to-end (`runSinglePackInstall → executeRunInstallPoolsAndWrite → installAsPack → materializePack/mergeIntoPack`) so `collectPreservedRootFiles(contentRoot)` harvests top-level `README*` / `LICENSE*` / `NOTICE*` / `COPYING*` / `COPYRIGHT*` into the pack root **before** `hashPackContent` runs — preserved files must participate in `content_hash` + the per-file install manifest so uninstall removes them automatically. [L278]
21. `OUTPUT_DIR_TO_FEATURE` and `stripMarkdownExt` in `src/core/reference/validate-generated-markdown-links.ts` must enumerate every target-specific dir (`droids`, `instructions`, `prompts`, `steering`, …) and every double-extension (`.agent.md`, `.instructions.md`, `.prompt.md`) so `canonicalKeyFromOutputPath` produces the same canonical key as the source entity. Treat as a single-source-of-truth table: new target = one row each. [L278]
22. Wrap the terminal `runGenerate()` in **both** `runInstall` and `runUninstall` in try/catch (extracted as `runPostOperationGenerate('install' | 'uninstall', scope, rootBase)` in `src/install/run/post-install-generate.ts`). Downgrade failures to `logger.warn(...)` naming the failure mode — the pack + `installs.yaml` writes are the user's intent and must survive validator brittleness. Same rule for any future best-effort post-operation step (e.g. post-install `agentsmesh lint`). [L258]
23. Per-target skill-import dispatch loops belong behind one `importSkillsDirectory(options, recognizers[])` orchestrator with factory recognizers (`projectedAgentRecognizer`, `commandSkillRecognizer`) that own their own destination write + stale cleanup. Per-target adapters collapse to a config object + recognizer list so new targets can't drift on cleanup order or recognizer ordering. [L252]
24. When persisting strict install manifest assertions, inspect the **actual serialized entry shape** first (including field omission and ordering) — don't write expectations from inferred intent. Whenever the manifest type gains required fields, sweep all `toHaveBeenCalledWith` / deep-equality assertions, not just the typed fixture. [L81, L157]
25. Whenever pack/install manifest persistence semantics change, rerun the full agents/commands/rules/skills matrix and the sibling-item amend cases — not only the user-reported entity. [L152]
26. Skill-pack integration fixtures with broken links must narrow the project's `features:` so the linking entity is NOT generated (e.g. `features: [rules]` when the broken link sits in a skill). Assert pack body + manifest there, not generated target files. Cross-protocol identity assertions (https/ssh/`github:` shorthand) belong in unit tests on `findExistingInstallName`, not integration. [L256]
27. Mock `ValidatedConfig` fixtures returned by `mockLoadScopedConfig.mockResolvedValue` must include every schema-defaulted field (`plugins: []`, etc.) because tests bypass schema validation. Adding any new orchestration step that reads `config.X` requires grepping for every mock and adding the field before rerunning. [L264]
28. Global import (`scope === 'global'`) must NOT pass `homedir()` as `projectRoot` for recursive scans. Only read tool-native subtrees under home (e.g. `~/.codex`, `~/.agents/skills`); never `readDirRecursive(homedir())` — symlink cycles under `~/.cache` will blow the stack. [L170]
29. Importers must clean stale reserved artifacts on re-import (e.g. `_ab-agent-*`, `_ab-command-*`, scoped-rule names). Extract shared filter/cleanup into one helper instead of copy-pasting per target. Import normalization must build the rewrite map from **every supported generated path family** so cross-target re-import recovers canonical `.agentsmesh/...` links from previously polluted outputs. [L145, L146, L147]
30. When a target-native filename changes, update generation/docs to the new path but keep importer fallbacks for the previous on-disk filename unless the migration is explicitly destructive. [L84]
31. Per-target import mappers (custom `ImportEntryMapper`) MUST live in `<target>/import-mappers.ts` — never in `importer.ts`. Putting them in `importer.ts` and importing from `index.ts` forms a cycle: `index.ts → importer.ts → index.ts`, and the descriptor's object literal captures `undefined` for `map:` fields. Function references stored as descriptor fields are safe (live bindings); object literals capturing those references at module-init are not. Establish `import-mappers.ts` even for one mapper. [L208, L212]
32. Don't migrate an `ignore` (or any single-output) feature to descriptor `flatFile` mode without re-reading the original importer. `flatFile` writes the FIRST `source` path verbatim — it never merges/dedupes. If the original concatenates multiple files (e.g. cursor merges `.cursorignore` + `.cursorindexingignore`), keep it imperative or extend the runner with `mergedFlatFile`. [L210]
33. `isLocalSource` for plugin paths must accept Windows drive-letter absolutes — match `/^[A-Za-z]:[/\\]/` alongside POSIX (`/…`, `./…`, `../…`, `file:`). Tests that build absolute paths with `resolve()` and feed them as plugin `source` exercise this. [L246]
