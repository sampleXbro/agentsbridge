# Lessons: link rebaser & reference rewriting

## Rules (apply unconditionally)

1. Treat reference-style Markdown definitions (`[ref]: ...`, titled, angle-bracketed) as link destinations, not prose anchors — apply the same destination-relative rewrite contract as inline links. (Evidence L42, L50)
2. Preserve well-known canonical tokens (e.g. `.agentsmesh/`) in prose/labels/quoted/reading-context positions, but rewrite real Markdown inline-link destinations cross-format. Audit prose vs link classifier whenever formatter semantics change. (Evidence L50, L92, L125)
3. Never inline `.agentsmesh/` as an exact substring in generated root-instruction decoration prose — reference-rewrite e2e strips fenced code and asserts the substring is gone. Phrase as ``the `.agentsmesh` directory at the project root``. Strip both old and new contract blocks on import. (Evidence L92, L163)
4. Add every emitted artifact path (including `additionalRootDecorationPaths`, multi-output families like Copilot's `.github/copilot/*.instructions.md` + `.github/instructions/*.md`, and Windsurf shared `AGENTS.md`) to the generate-side output-source map and build rewrite maps per output path / artifact family, not just per target. (Evidence L63, L128, L131)
5. Pack skill artifact paths (`.agentsmesh/packs/.../skills/...`) must be added to `buildArtifactPathMap` alongside canonical `.agentsmesh/skills/...` so the rebaser translates both canonical and pack absolute paths. (Evidence L162)
6. Shared artifact collision must compare canonicalized (un-rewritten) content, not post-rewrite bytes — collapse target-specific rewritten links back to canonical before declaring a true conflict. Keep target-native rewrite probes in protected fenced blocks or target-filtered fixtures so they don't poison shared outputs. (Evidence L44, L123)
7. Existence-gate rewriting: classify "should rewrite" vs "should stay unchanged because resolution fails" explicitly. Don't blindly normalize relative-looking refs whose targets don't exist (e.g. missing checklist refs, fixture `../SKILL.md`). Audit both categories whenever the link contract changes. (Evidence L129)
8. For bare multi-segment paths under a root-relative contract (`src/AGENTS.md`, `docs/...`), resolve from the project root first, fall back to source-relative only if the root candidate is invalid. Add nested-file regression tests. (Evidence L130)
9. For `../` over-traversal that escapes the workspace, retry resolution from the project root before giving up — real canonical files contain `../../../../docs/...` that still mean repo-root files. Cover in unit + all-target generate/import matrices. (Evidence L136)
10. Preserve/add `./` prefix for same-directory descendant links inside generated Markdown (`formatLinkPathForDestination`). Assert the exact rendered path (`./skills/post-feature-qa/`) in tests, never "not canonical" loose matches. (Evidence L64)
11. URI-skip patterns (`ssh://`, `git@host:`) must keep the scheme matcher distinct from Windows drive-letter detection — never let a single-letter scheme regex swallow `C:` and block legitimate absolute paths. Add same-file regression for both. (Evidence L135)
12. Path tokenizers must require enough structure to distinguish file references from prose markers — the absolute-path branch must NOT match a bare `/` (e.g. `✓ / ✗` status text). (Evidence L133)
13. Inline backtick path rewrites: tests asserting the rewritten form must accept any of `` `docs/...` ``, `` `/docs/...` ``, `` `./docs/...` ``, `` `../docs/...` `` via a permissive regex — Windows 8.3-shortname realpath divergence makes the exact form non-deterministic. The contract is "stable destination," not "always project-root-relative." (Evidence L202)
14. `expandResolvedPaths` must yield the caller's `projectRoot`-shaped path FIRST, then the realpath variant as a tie-breaker — never `unshift(realPath)`. Realpath-first breaks `toProjectRootRelative` on DOS short names (`RUNNER~1` vs `runneradmin`) and symlinked tmpdirs. Audit every `[realpath, original]` loop. (Evidence L203)
15. Import normalization must include BOTH the direct joined target path AND its `realpathSync.native` variant in the lookup map. Temp-workspace runs resolve through realpath and otherwise stay target-specific after import. (Evidence L132)
16. Import normalization must build the rewrite map from every supported generated path family across ALL targets, not just the source target — re-importing a polluted artifact must recover canonical `.agentsmesh/...` links cross-family. (Evidence L147)
17. Do not normalize bare root filenames (`AGENTS.md`, `CLAUDE.md`, `.windsurfrules`, `GEMINI.md`) as raw substrings on the import side — they are common standalone words in prose. Only normalize when they appear in a structured path form. (Evidence L125)
18. Any code participating in the link-rewrite map (key construction OR lookup) MUST use `pathApi(projectRoot)` from `src/core/path-helpers.ts`. NEVER import `join`/`normalize` from `node:path` directly in `src/core/reference/` or target-side `applyXxxRefs` helpers. (Evidence L198)
19. Unit tests using a synthetic POSIX root (e.g. `ROOT = '/proj'`) with link-rewrite map machinery must alias `join`/`normalize` to `posix.join`/`posix.normalize` from `node:path/posix` — host `node:path` is win32 on Windows runners and silently mismatches the map. (Evidence L200)
20. After extracting helpers from `link-rebaser.ts` (e.g. `normalizeSeparators`, formatter helpers), scan every remaining branch (especially preservation/protected paths) for moved symbols and rerun the narrowest affected suite BEFORE expanding verification. (Evidence L182)
21. Whenever the link-rewriter protection contract changes (fenced code, inline backticks, URI skips, drive letters), update both the main rewrite tests AND `link-rebaser-edge-cases.test.ts` in the same pass — the edge-case suite codifies the same contract separately. (Evidence L137)
22. Reference-rewrite audits must search REAL canonical content for path patterns (including directory-form refs like `.agentsmesh/skills/post-feature-qa/`) and add tests for both exact files AND directory-form references. Synthetic round trips are insufficient — regenerate live target artifacts and grep the exact reported pattern. (Evidence L106, L122)
23. Generated Markdown demo content must use link destinations that resolve from EVERY generated target folder after rebasing. Keep speculative project-root examples as prose, not as clickable Markdown destinations. (Evidence L45)
24. When parsing inline-link destinations with regex captures (e.g. `parseMarkdownLinkDestination`), guard the specific capture explicitly (`match?.[1] !== undefined`) under strict indexed access — don't rely on regex structure. (Evidence L61)
25. Before adding extension-level skip gates in `rewriteGeneratedReferences()`, inspect the reference-rewrite matrix — supporting files like `template.ts` comments must still be rewritten; only token/comment-aware logic, not a blanket non-Markdown skip. (Evidence L13)
26. Strict-prose assertions ("no leftover canonical mesh path") must run on prose with ALL rewriter-protected tokens stripped (fenced code, external refs, AND Windows absolute path tokens `/[A-Za-z]:[\\/][^\s,<>"'+'`'+`]+/`). The `WINDOWS_ABSOLUTE_PATH` guard in `link-rebaser.ts` is by-design. (Evidence L204)
