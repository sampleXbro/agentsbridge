# Lessons: shell quoting & inline scripts

## Rules (apply unconditionally)

1. For inline Node scripts that use top-level `await`, use ESM `import` syntax; otherwise wrap CommonJS `require` code in an async IIFE. Never mix `require` with top-level `await` in the same heredoc — Node 24 emits `ERR_AMBIGUOUS_MODULE_SYNTAX`.
2. Never put escaped newlines (`\n`) inside a plain `rg` regex; ripgrep is line-oriented by default. Split into multiple literal patterns, or pass `rg -U --multiline-dotall` when a true cross-line match is required.
3. Never assign to `status` (or other zsh read-only specials) in shell cleanup snippets — use neutral names like `rc` for captured exit codes. Verify cleanup ran when the sandbox/wrapper exits unexpectedly.
4. For `rg` patterns containing backticks, `$`, or other shell metacharacters, use single quotes with `-F` (literal mode), or split into simpler literal patterns. Never wrap such patterns in double quotes — the shell command-substitutes the backticks before `rg` ever runs.
5. For `execSync`/`spawnSync` calls that need shell features like `2>&1`, use `/bin/sh` (or omit `shell` and avoid shell-only syntax). Never hardcode `/bin/zsh` (missing on `ubuntu-latest`) or `/bin/bash` (not guaranteed on minimal images) unless the job explicitly installs that shell.
6. For tests that need merged stdout+stderr cross-platform, use `spawnSync(process.execPath, [...args], { encoding: 'utf-8' })` and concatenate `result.stdout + result.stderr`. Never embed `2>&1` or hardcode any `/bin/*` once Windows is in the CI matrix.
7. Never write a literal `*/` inside any `/* ... */` or `/** ... */` block comment — including JSDoc headers in test files. Globs like `skills/*/SKILL.md` close the comment early and produce misleading parser errors at unrelated lines. Reword to `skills/{name}/SKILL.md`, `glob: *.md`, or move into a `//` single-line comment.
8. When a TS/JS source file needs control-character escapes inside regex literals, build the regex via `new RegExp('[<>:"|?*\\u0000-\\u001F]')` or `String.fromCharCode(n)` — never put `\xNN`/`\uNNNN` directly in a `Write` tool payload, because JSON evaluates them into raw control bytes before the file is written. Verify the resulting file with `file(1)` is reported as text, not `data`.
9. When a fixture string needs literal `<<<<<<< HEAD` / `=======` / `>>>>>>>` lines at module top level, either (a) inline the literal inside a CallExpression argument, or (b) build it from concatenated parts (`'<' + '<<<<<< HEAD'`) so no source line begins with seven repeated `<`/`=`/`>`. TypeScript's lexer scans for left-anchored merge-conflict markers even inside top-level template literals (TS1185).
10. Installer scripts that auto-edit shell rc files must key BOTH the rc file path AND the line syntax off the shell name. `export PATH=...` is bash/POSIX-only — fish rejects it. For fish, use `fish_add_path -gP "$BIN_DIR"` (or `set -gx PATH "$BIN_DIR" $PATH`). Always `mkdir -p "$(dirname "$config")"` before `>>` because `~/.config/fish/` may not exist.
11. When parsing structured `<token>  <filename>` manifests (checksums, etc.) from shell, use `awk -v t="$TARGET" '$2==t {print $1}'` — field equality, not `grep "$NEEDLE"` substring. Substring matching silently breaks when filenames share prefixes (e.g., `agentsmesh-darwin-arm64` vs `agentsmesh-darwin-arm64.exe`).
12. Validate env-controlled paths (e.g., `$AGENTSMESH_INSTALL`) against a strict allowlist (`*[!a-zA-Z0-9./_~\ -]*`) before interpolating into any line written to a shell-rc file. Otherwise a wrapping process can inject persistent shell code via the env var.
13. When a build/test fails with parser errors ("Unterminated string literal", "Unexpected `<<`"), scan touched files for unresolved `<<<<<<<` merge conflict markers FIRST before deeper investigation — higher-level debugging on a syntactically invalid file is noise.
14. When an `rg` search pattern starts with `-` (or may start with `-` after interpolation), pass it with `-e '<pattern>'` or place `--` before the pattern so ripgrep cannot parse the search text as flags. (Evidence: L288)
