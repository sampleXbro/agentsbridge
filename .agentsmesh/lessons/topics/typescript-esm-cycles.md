# Lessons: TypeScript & ESM cycles

## Rules (apply unconditionally)

1. Place every per-target `ImportEntryMapper` referenced by the descriptor object literal in a third file `src/targets/<id>/import-mappers.ts`. Never let `index.ts` import mappers from `importer.ts` and `importer.ts` import the descriptor from `index.ts` — the object literal will capture `undefined` for `map:` fields and silently break import. Create `import-mappers.ts` even when there is only one mapper.
2. When auto-generating module-level data (e.g. `BUILTIN_TARGETS`) from per-target descriptor imports, patch the existing source file in place between sentinel comments `// <auto-generated:...>` ... `// </auto-generated:...>`. Do NOT extract the array literal to a new generated module — array literals evaluate eagerly and indirection through a separate file adds one more cycle hop that snapshots TDZ-pending imports as `undefined`.
3. Any lazy registry cache built over `BUILTIN_TARGETS` (or another descriptor-derived list whose own callbacks can trigger the cache during module init) MUST detect TDZ holes (`BUILTIN_TARGETS.filter((d) => d !== undefined)`) and refuse to cache until every slot is populated. "Lazy = safe from cycles" is false; lazy caches that capture mid-init state are worse than no cache.
4. Whenever a core type becomes a union (e.g. `McpServer` gaining a URL-transport variant), add explicit type guards at every serializer/generator boundary that requires a specific variant, and rerun `pnpm typecheck` before declaring the refactor done.
5. Read regex capture groups under `noUncheckedIndexedAccess` only after narrowing the capture itself: `match?.[1] !== undefined` (or store the value first). Do not rely on regex structure to "guarantee" a capture; the type system does not.
6. Use explicit strict null comparisons (`!== null` / `!== undefined`). Do not use `!= null` shorthand — the repo lint gate rejects it.
7. Import Node platform globals (`URL`, `tmpdir`, etc.) explicitly from their `node:` modules. `URL` comes from `node:url`; `tmpdir` from `node:os` (NOT `node:path`); `join`/`resolve` from `node:path`. Ambient Node globals are not implicit under this ESLint config.
8. After any refactor that touches branch conditions, destructuring, helper extraction, or parsing/normalization control flow, immediately rerun `pnpm lint` AND `pnpm typecheck` — do not defer to broader verification. Sweep dead guard variables that fed the old condition; split destructured returns into `const` for immutable values and a separate `let` only for the one value that is actually reassigned.
9. When extracting helpers, scan the remaining file for every symbol that moved and run the narrowest affected test suite immediately — do not assume "mechanical split" is safe. A preservation branch left over with a removed import surfaces as `ReferenceError` only at runtime.
10. When a target's `rewriteGeneratedPath` or layout references a constant (e.g. `CURSOR_COMPAT_AGENTS`), re-audit the `index.ts` import list at edit time. Treat missing-symbol `ReferenceError` from CLI generate as a release gate, not a runtime curiosity.
11. Single-letter URI scheme regexes (`^[a-z]+:`) must be kept distinct from Windows drive-letter detection (`^[A-Za-z]:[/\\]`). A scheme matcher that swallows `C:` will block legitimate Windows absolute paths from rewriting. Add regression tests covering both shapes in the same file.
12. In `resolveGen` and similar dispatchers with a plugin-registry fallback, check `getBuiltinTargetDefinition(target)` FIRST and delegate to `resolveTargetFeatureGenerator(target, feature, config)` for builtins; otherwise the plugin fallback re-applies the raw generator and bypasses conversion config (e.g. `commandsToSkills: false`). Do not let a generic descriptor lookup serve as the builtin path.
13. Never write a literal `*/` inside any `/* ... */` block comment (including JSDoc and file-header blocks). Replace `skills/*/SKILL.md`-style globs in prose with `skills/{name}/SKILL.md` or move them to single-line `//` comments. The same hazard breaks both production sources and test files.
14. (also relevant — primary in `fixture-and-assertion-discipline`) When a command-orchestration test mocks `loadScopedConfig`, the mocked `ValidatedConfig` must include every field the schema defaults populate (e.g. `plugins: []`). Adding an orchestration step that reads `config.X` without updating every `mockLoadScopedConfig.mockResolvedValue` fixture crashes on `undefined`.
15. Do not mix CommonJS `require(...)` with top-level `await` in inline `node -e` / heredoc scripts under modern Node — it triggers `ERR_AMBIGUOUS_MODULE_SYNTAX`. Use ESM `import`, or wrap CJS in an async IIFE.
