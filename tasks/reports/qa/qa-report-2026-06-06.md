## Findings (Ordered by Severity)

### 1. [MEDIUM] `import-md` crashes with raw `ENOENT` when no legacy `index.yaml` exists
- **Repro:**
  - `cd $(mktemp -d) && node dist/cli.js lessons import-md` (or with `--force`)
  - Also triggers when re-running `import-md --force` after a successful migration already deleted the legacy files.
- **Expected:** A clean, actionable message, e.g. `No legacy lessons found at .agentsmesh/lessons/index.yaml — nothing to migrate.` with a controlled exit code.
- **Actual:** Unhandled Node fs error surfaced to the user, leaking an absolute filesystem path:
  ```
  ✗ ENOENT: no such file or directory, open '/private/tmp/lessons-empty.atoHEP/.agentsmesh/lessons/index.yaml'
  ```
  With `--verbose` a full stack trace is printed (`readFileSync` → `importLegacyLessons` → `doImportMd`).
- **Evidence / root cause:** `src/lessons/import-legacy.ts:62` — `const indexRaw = readFileSync(paths.index, 'utf8');` has **no `existsSync` guard**, even though the same function guards per-topic files at line 75 (`if (!existsSync(topicFile)) …`). The `--force` flag short-circuits the "graph already exists" check and proceeds straight into the unguarded read.
- **Impact:** `import-md` is a documented subcommand (listed in `lessons --help`). The overwhelmingly common state today is "lessons.json present, no legacy store"; any user who runs `import-md` to explore it hits a raw crash that leaks paths rather than a friendly no-op. Low blast radius (read-only failure, no corruption) but poor UX on a first-class command.
- **Suggested fix:** In `doImportMd` (or `importLegacyLessons`), pre-check `existsSync(paths.index)` and return a clean "nothing to migrate" message + non-crashing exit.

### 2. [LOW] `query --format` silently accepts invalid values
- **Repro:** `node dist/cli.js lessons query --keyword commit --format xml`
- **Expected:** Rejection consistent with the numeric validators, e.g. `Invalid --format: expected plain|md|json.`, exit 2.
- **Actual:** Invalid value is silently ignored; output falls back to plain, exit 0.
- **Evidence:** Test cases #34 — `--format xml` produced the same output as `--format plain` with no warning.
- **Impact / inconsistency:** `--top`, `--max-tokens` reject bad values strictly (exit 2), but `--format` does not. A typo (`--format jso`) silently yields the wrong format. Cosmetic, easy to miss.
- **Suggested fix:** Have `parseFormat` throw a usage error on any value outside `plain|md|json`.

### 3. [LOW] Global flags placed *before* the command name misparse
- **Repro:** `node dist/cli.js --json lessons topics` and `node dist/cli.js --verbose lessons import-md`
- **Expected:** Either honor the global flag regardless of position, or emit a clear "flags must follow the command" message.
- **Actual:** The first positional after the flag is swallowed, so `lessons` is dropped and `topics` is interpreted as the top-level command:
  ```
  ✗ Unknown command "topics". Available: generate, init, import, … lessons
  ```
- **Evidence:** Test case #40. Works correctly when the flag is placed after the command (`lessons query … --json` → proper envelope).
- **Impact:** CLI-wide arg-parsing footgun surfaced via lessons. `lessons --help` lists `--json`/`--verbose` under "Global flags" with no positional caveat, so users may reasonably place them first. Workaround exists (put flags last). Not lessons-specific.
- **Suggested fix:** Normalize global-flag handling to be position-independent, or document/validate the required ordering.

## Resolution — All Findings Fixed (same session)

All three findings were fixed under TDD (failing tests written first, then implementation). Full suite green afterward: **8323 passed / 1 skipped**, typecheck + lint clean.

| Finding | Fix | Files |
|---------|-----|-------|
| #1 import-md `ENOENT` | Guard in `doImportMd`: when `.agentsmesh/lessons/index.yaml` is absent, return a clean `No legacy lessons store found … — nothing to migrate.` (exit 1) instead of reaching the unguarded `readFileSync`. Stale "no-op" docstring on `importLegacyLessons` corrected to state callers must guard. | `src/cli/commands/lessons-write-handlers.ts`, `src/lessons/import-legacy.ts` |
| #2 `--format` not validated | New `validateFormatFlag` in `doQuery` rejects any `--format` value outside `plain\|md\|json` with `Invalid --format: expected plain\|md\|json.` (exit 2), matching the `--top`/`--max-tokens` validators. | `src/cli/commands/lessons-handlers.ts` |
| #3 global flags before command | `parseArgs` now treats a small set of provably boolean-only globals (`json`, `verbose`, `help`) as valueless so they never swallow the following command token. `--version` deliberately excluded (it is value-taking for `plugin add --version <ref>`). | `src/cli/index.ts` |

**Tests added (all red→green):**
- `tests/unit/cli/index.test.ts` — `--json`/`--verbose` before the command keep the command name.
- `tests/unit/cli/commands/lessons.test.ts` — invalid `--format` exit 2; `import-md` with no legacy store gives a clean error (no `ENOENT`), with and without `--force`.

**Regression caught during fix (and itself fixed + captured as a lesson):** an initial version of fix #3 also marked `--version` valueless, which broke `plugin add --version <ref>` (the e2e `plugin.e2e` suite caught it). Narrowed the set to boolean-only flags; lesson recorded in the lessons graph (`lessons-system-before-adding-a-flag-name`).

Post-fix manual re-verification via the rebuilt CLI confirmed all three behaviors and that `--version` / `plugin add --version` still work.

## Release Verdict

**PASS (with three non-blocking findings).**

**Rationale:** Every lessons CLI subcommand and every MCP tool works correctly on the happy path and on the important failure paths. Data integrity is sound — writes are atomic and transactional (invalid input rolls back with zero orphaned triggers), idempotency holds across both CLI and MCP, exit codes are coherent (usage errors → 2, semantic errors → 1), and legacy migration is correct and self-cleaning. All 119 lessons tests + typecheck are green. The real project graph was left byte-identical to its committed state.

The three findings are UX/validation polish, not correctness or data-safety defects:
- **#1 (medium)** — ugly unhandled `ENOENT` on `import-md` with no legacy store; worth fixing because it's a documented command that leaks paths and crashes on the most common state.
- **#2 / #3 (low)** — input-validation inconsistencies (`--format` not validated; global flags position-sensitive).

**Recommended next actions:**
1. Guard `readFileSync(paths.index)` in `src/lessons/import-legacy.ts:62` (or in `doImportMd`) → clean "nothing to migrate" message. *(Finding #1)*
2. Validate `--format` values in `parseFormat`. *(Finding #2)*
3. Make global-flag parsing position-independent or validate ordering. *(Finding #3)*
